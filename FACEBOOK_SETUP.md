# Facebook Integration Setup

How the archery website pulls the club's Facebook posts into the news feed, and
the exact steps to get it working. This document has **two audiences**:

- **Part A — for the developer (you):** what you can prepare *now*, before the
  club is involved.
- **Part B — for the club's Facebook Page admin:** the steps to generate the
  access token the website needs. Written so a non-technical person can follow
  it (or so you can guide them through it).

> ⚠️ **Accuracy note:** Meta changes its Developer dashboard UI and policies
> frequently. The *concepts* below are correct and verified against Meta's
> documentation (see Sources). The exact button labels / menu positions may
> differ slightly from what you see — confirm against the live dashboard as you
> go. Where a step is UI-dependent, it's flagged.

---

## How it works (the short version)

The website's **backend** calls the Facebook **Graph API** every 6 hours to read
the club Page's posts, then stores them as articles. To do that, the backend
needs a **Page Access Token** — a credential that authorizes reading the Page's
posts.

A Page Access Token can only be generated by an **admin of the Facebook Page**
(i.e. the club). The token is a secret: it lives only in the backend's
environment config, never in the website's code or the frontend.

Three things must exist:
1. A **Meta Developer App** (you create this).
2. The **`pages_read_engagement`** permission granted on it (the Page admin
   grants this).
3. A **long-lived (non-expiring) Page Access Token** (generated from the above).

---

## Part A — What the developer can prepare NOW (before the club)

You can do most of the groundwork without the club. You **cannot fully finish**
without them (the token requires a Page admin), but you can get everything ready
so that when the club says yes, it's a short final step.

### A1. Create a Meta Developer account
- Go to <https://developers.facebook.com/> and log in with a Facebook account.
- Register as a developer if prompted (free).

### A2. Create an App
- In the dashboard: **My Apps → Create App**.
- App type: choose **Business** (this is the type that exposes the Pages API /
  `pages_read_engagement`). *(UI-dependent — Meta sometimes reworks the app-type
  picker; pick the type whose use case is "Manage business integrations / access
  Pages data".)*
- Give it a name (e.g. "VSK Archery Website").

### A3. Add the Pages API product
- In the app, add the product that grants Page access (historically
  **"Facebook Login"** + the **Pages API**). *(UI-dependent.)*
- Under **App Review → Permissions and Features**, locate
  **`pages_read_engagement`**. In development mode you can use it with people who
  have a role on the app (see A4) without full review.

### A4. (Optional, for testing now) Add yourself / testers
- In development mode, the app can read Pages where the *user* is an admin and
  has a role on the app. So if you ever get a *test* page you control, you can
  validate the whole pipeline before the club is involved.

### A5. Know what App Review will require (so there are no surprises)
To run in **production** (reading a Page you don't own, continuously), Meta
generally requires:
- **App Review** for `pages_read_engagement` — you submit a description + a
  screencast showing how the app uses the data.
- **Business Verification** of the app's associated business.
- The **Page admin (club)** to grant the permission.

> You can prepare the App Review submission text/screencast in advance, but the
> review **cannot complete** until the club has connected their Page and granted
> access. Plan for this to take time (Meta review is not instant).

## Part B — Steps for the club's Page admin (to generate the token)

Give this section to whoever administers the **Varaždinski streličarski klub**
Facebook Page, or walk them through it. They will need to be logged into
Facebook as a Page admin.

> The developer (you) must have completed Part A first and must tell the club
> admin the **App name** to select in step 2.

### B1. Open the Graph API Explorer
- Go to <https://developers.facebook.com/tools/explorer>.

### B2. Select the app
- In the **Facebook App** dropdown (top right), select the app the developer
  created (e.g. "VSK Archery Website").

### B3. Get a User Access Token with the right permission
- Click the **dropdown → "Get User Access Token"**.
- In the permissions list, tick **`pages_read_engagement`** (and
  `read_insights` if engagement stats are wanted later).
- Click **Generate Access Token**.
- A Facebook login/consent popup appears → log in and **grant** the requested
  permissions, and make sure the **club Page is selected/subscribed** when asked.

### B4. Switch to a Page Access Token
- Click the **token dropdown again** → under your Pages, select the **club's
  Page**.
- The Explorer now shows a **Page Access Token** (this is the one tied to the
  Page, not your personal account).

### B5. Make it long-lived (non-expiring)
The token from B4 is short-lived (expires in ~1 hour). To get one that doesn't
expire:
1. **Exchange the short-lived user token for a long-lived one** (≈60 days):
   ```
   https://graph.facebook.com/v23.0/oauth/access_token?
     grant_type=fb_exchange_token&
     client_id={APP_ID}&
     client_secret={APP_SECRET}&
     fb_exchange_token={SHORT_LIVED_USER_TOKEN}
   ```
   (`APP_ID` / `APP_SECRET` come from the app's **Settings → Basic** — the
   developer provides these.)
2. **Request the Page token using the long-lived user token** — call the `me/accounts`
   endpoint with the long-lived user token; the Page token returned in that
   response **does not expire** as long as the user token was long-lived and the
   admin keeps their role:
   ```
   https://graph.facebook.com/v23.0/me/accounts?access_token={LONG_LIVED_USER_TOKEN}
   ```

### B6. Verify the token
- Go to the **Access Token Debugger**:
  <https://developers.facebook.com/tools/debug/accesstoken/>
- Paste the Page token. Confirm:
  - **Type:** Page
  - **Expires:** Never
  - **Valid:** True

### B7. Hand the token to the developer **securely**
- The Page Access Token is a **secret**. Do **not** email it in plain text or
  post it in a chat. Use a password manager share, an encrypted message, or
  hand it over in person.
- The developer puts it in the backend's `.env` (e.g. `FB_PAGE_ACCESS_TOKEN=...`)
  — it never goes into any website code or repository.

---

## What happens after the token is in place

- The backend's 6-hour sync job activates (it's dormant/stubbed until the token
  exists).
- New club posts get imported as articles automatically.
- The admin dashboard's per-post **Sync** buttons become active.
- Until then, the website runs on the curated **mock data** (the ~40 posts
  gathered manually).
